# 8. 입출력장치

## 8-1. 장치 컨트롤러와 장치 드라이버

### 장치 컨트롤러

#### 입출력 장치가 까다로운 이유

1. 종류가 너무 많아 장치마다 속도, 데이터 전송 형식 등이 다양하다. 따라서 다양한 입출력장치와 정보를 주고받는 방식을 규격화하기 어렵다.

2. 일반적으로 CPU와 메모리의 데이터 전송률은 높지만 입출력장치의 데이터 전송률은 낮다.

- 전송률(transfer rate) : 데이터를 얼마나 빨리 교환할 수 있는지를 나타내는 지표

이러한 이유로 입출력장치는 컴퓨터에 직접 연결되지 않고 장치 컨트롤러(device controller)라는 하드웨어에 연결된다.

- 입출력 제어기(I/O controller), 입출력 모듈(I/O module) 등으로 부르기도 한다.

#### 장치 컨트롤러의 역할

- CPU와 입출력장치 간의 통신 중개
- 오류 검출
- 데이터 버퍼링

##### 데이터 버퍼링(buffering)

- 버퍼링 : 전송률이 높은 장치와 낮은 장치 사이에 주고받는 데이터를 버퍼(buffer)라는 임시 저장 공간에 저장해 전송률을 비슷하게 맞추는 방법

즉, 장치 컨트롤러는 전송률이 높은 CPU와 전송률이 낮은 입출력장치와의 전송률 차이를 데이터 버퍼링으로 완화한다.

#### 장치 컨트롤러의 구조

<img src="../../images/Basic/os-1-8-1.PNG">

- 데이터 레지스터

  - CPU와 입출력장치 사이에 주고받을 데이터가 담기는 레지스터
  - 버퍼 역할을 한다.
  - 주고받는 데이터가 많을 경우 레지스터 대신 RAM을 사용하기도 한다.

- 상태 레지스터

  - 입출력장치가 입출력 작업을 할 준비가 되었는지, 입출력 작업이 완료되었는지, 입출력장치에 오류는 없는지 등의 상태 정보가 저장된다.

- 제어 레지스터
  - 입출력장치가 수행할 내용에 대한 제어 정보와 명령을 저장한다.

### 장치 드라이버(device driver)

장치 컨트롤러의 동작을 감지하고 제어함으로써 장치 컨트롤러가 컴퓨터 내부와 정보를 주고받을 수 있게 하는 프로그램

이 때, 장치 드라이버는 운영체제가 인식하고 실행한다.

컴퓨터가 연결된 장치의 드라이버를 인식하고 실행할 수 있다면 정보를 주고받을 수 있다.

## 8-2. 다양한 입출력 방법

장치 컨트롤러와 CPU는 어떻게 정보를 주고 받을까

### 입출력 인터페이스 방식

장치가 CPU와 어떻게 연결되어 있는지

메모리 맵 입출력, 고립형 입출력 방식이 있다.

#### 메모리 맵 입출력(memory-mapped I/O)

입출력 장치의 제어 레지스터와 버퍼를 메모리 주소 공간에 포함시켜서, 마치 메모리에 접근하듯 장치에 접근하는 방식

장치 레지스터와 일반 메모리 주소가 같은 주소 공간을 공유해, 메모리 공간 일부를 I/O 장치가 차지하게 된다.

- 장점

  - 메모리에 접근하는 명령어와 입출력장치에 접근하는 명령어가 같다.
  - 메모리처럼 자유롭게 접근 가능하기 때문에 프로그램 작성이 유연하다.

- 단점
  - I/O 장치가 주소를 차지하기 때문에 메모리 주소 공간이 줄어든다.

#### 고립형 입출력(isolated I/O)

메모리를 위한 주소 공간과 입출력장치를 위한 주소 공간을 분리하는 방법

입출력장치에 접근하기 위해 메모리에 접근하는 명령어와는 다른 입출력 명령어를 사용한다.

- 장점

  - 메모리 공간을 전혀 차지하지 않아, 메모리 주소를 온전히 데이터용으로 사용할 수 있다.
  - 입출력과 메모리 간 명확한 구분이 가능하다.

- 단점
  - I/O 장치 제어를 위해 특수한 명령어가 필요하다.
  - 명령어가 제한되어 유연성은 떨어진다.

### 입출력 처리 방식

소프트웨어 관점에서 입출력을 언제, 어떻게 처리하는지

CPU가 입출력을 직접 처리 vs 인터럽트나 DMA 등으로 위임

#### 프로그램 입출력(Programmed I/O)

프로그램 속 명령어로 입출력 장치를 제어하는 방법

1. CPU가 하드 디스크 컨트롤러의 제어 레지스터에 쓰기 명령을 보낸다.

2. 하드 디스크 컨트롤러는 하드 디스크의 상태를 확인하고, 준비된 상태라면 상태 레지스터에 준비되었다고 표시한다.

3. CPU는 상태 레지스터를 주기적으로 읽어보며 하드 디스크의 준비 여부를 확인한다.

4. 하드 디스크가 준비되었음을 CPU가 알게 되면 백업할 메모리의 정보를 데이터 레지스터에 쓴다. 아직 준비되지 않았다면 3번부터 반복한다.

5. 쓰기가 끝났다면 작업을 종료한다.

프로그램 입출력 방식에서의 입출력 작업은 CPU가 장치 컨트롤러의 레지스터 값을 읽고 쓰면서 이루어진다.

#### 인터럽트 기반 입출력(Interrupt I/O)

CPU는 장치 컨트롤러에 입출력 작업을 명령하고, 장치 컨트롤러가 입출력장치를 제어하며 입출력을 수행하는 동안 CPU는 다른 일을 할 수 있다.

> 폴링(polling)
>
> - 입출력장치의 상태는 어떤지, 처리할 데이터가 있는지를 주기적으로 확인하는 방식
>
> - 인터럽트 방식보다 CPU의 부담이 더 크다.

여러 인터럽트가 동시에 발생한다면?

- 인터럽트가 발생한 순서대로 인터럽트를 처리할 수 있다.

- CPU가 플래그 레지스터 속 인터럽트 비트를 비활성화한 채 인터럽트 처리 -> 다른 입출력장치에 의한 하드웨어 인터럽트를 받아들이지 않음 -> 순차적으로 처리

- 이 때, 인터럽트 중에서도 더 빨리 처리해야 하는 인터럽트가 있다.

- 따라서, CPU는 인터럽트 간 우선순위를 고려해 우선순위가 높은 인터럽트 순으로 처리할 수 있다.

- 플래그 레지스터속 인터럽트 비트가 활성화되어 있는 경우, 무시할 수 없는 인터럽트인 `NMI(Non-Maskable Interrupt)`가 발생한 경우 우선순위가 높은 인터럽트부터 처리한다.

##### 프로그래머블 인터럽트 컨트롤러(PIC: Programmable Interrupt Controller)

- 여러 장치 컨트롤러에 연결되어 장치 컨트롤러에서 보낸 하드웨어 인터럽트 요청들의 우선순위를 판별한 뒤 CPU에 지금 처리해야 할 하드웨어 인터럽트는 무엇인지 알려주는 장치

- 각 핀에 CPU에 하드웨어 인터럽트 요청을 보낼 수 있는 약속된 하드웨어가 연결되어 있다.

1. PIC가 장치 컨트롤러에서 인터럽트 요청 신호를 받아들인다.

2. PIC는 우선순위를 판단한 뒤 처리해야 할 인터럽트 요청 신호를 CPU에 보낸다.

3. CPU는 PIC에 인터럽트 확인 신호를 보낸다.

4. PIC는 데이터 버스를 통해 CPU에 인터럽트 벡터를 보낸다.

5. CPU는 인터럽트 벡터를 통해 인터럽트 요청의 주체를 알게 되고, 해당 장치의 인터럽트 서비스 루틴을 실행한다.

- 일단적으로 PIC를 두 개 이상 계층적으로 구성해 더 많고 복잡한 장치들의 인터럽트를 관리한다.

- NMI까지 우선순위를 판별하지는 않는다.(우선순위가 가장 높기 때문)

#### DMA 입출력

프로그램 기반 입출력, 인터럽트 입출력은 입출력장치와 메모리 간 데이터 이동은 CPU가 주도하고, 이동하는 데이터도 반드시 CPU를 거친다.

입출력장치 데이터를 메모리에 저장하는 경우

1. 장치 컨트롤러에서 입출력장치 데이터를 하나씩 읽어 레지스터에 적재한다.

2. 적재한 데이터를 메모리에 저장한다.

이 때, 입출력장치와 메모리 사이에 전송되는 모든 데이터가 반드시 CPU를 거쳐야 한다면 CPU의 부담이 커진다.

따라서 입출력장치와 메모리가 CPU를 거치지 않고도 상호작용할 수 있는 입출력 방식인 `DMA(Direct Memory Access)`가 등장했다.

DMA 입출력을 위해서는 시스템 버스에 연결된 `DMA 컨트롤러`라는 하드웨어가 필요하다.

##### DMA 입출력 과정

1. CPU는 DMA 컨트롤러에 입출력장치의 주소, 수행할 연산, 메모리 주소 등과 같은 정보로 입출력 작업을 명령한다.

2. DMA 컨트롤러는 CPU 대신 장치 컨트롤러와 상호작용하며 입출력 작업을 수행한다. 필요한 경우 메모리에 직접 접근하여 정보를 읽거나 쓴다.

3. 입출력 작업이 끝나면 DMA 컨트롤러는 CPU에 인터럽트를 걸어 작업이 끝났음을 알린다.

즉, CPU는 오로지 입출력의 시작과 끝에만 관여한다.

이 때, DMA 컨트롤러는 시스템 버스로 메모리에 직접 접근하지만, 시스템 버스는 동시 사용이 불가능하다.

그래서 DMA 컨트롤러는 CPU가 시스템 버스를 이용하지 않을 때마다 조금씩 이용하거나, CPU가 일시적으로 시스템 버스를 이용하지 않도록 허락을 구하고 집중적으로 이용한다.

이러한 DMA의 시스템 버스 이용을 `사이클 스틸링(cycle stealing)`이라 한다.

##### 입출력 버스

CPU, 메모리, DMA 컨트롤러, 장치 컨트롤러가 모두 같은 버스를 공유하면, DMA가 메모리에 한 번 접근할 때마다 시스템 버스를 두 번 사용하게 된다.

1. 메모리에서 DMA 컨트롤러로 데이터를 가져오기 위해 사용

2. DMA 컨트롤러의 데이터를 장치 컨트롤러로 옮기기 위해 사용

DMA가 시스템 버스를 너무 자주 사용하면 그만큼 CPU가 시스템 버스를 이용하지 못한다.

이 문제는 DMA 컨트롤러와 장치 컨트롤러들을 `입출력 버스(input/output bus)`라는 별도의 버스에 연결해 해결한다.

DMA 컨트롤러와 장치 컨트롤러가 서로 데이터를 전송할 때는 시스템 버스를 이용할 필요가 없어 시스템 버스의 사용 빈도를 줄일 수 있다.

<img src="../../images/Basic/os-1-8-2.PNG">

입출력 버스에는 `PCI(Peripheral Component Interconnect) 버스`, `PCI Express(PCIe) 버스` 등 여러 종류가 있다.

여러 입출력장치들은 PCIe 버스와 `PCIe 슬롯`이라는 하드웨어를 통해 연결된다.

> 최근에는 입출력 전용 CPU가 만들어지기도 했는데, 이를 입출력 프로세서(IOP; Input/Output Processor) 혹은 입출력 채널(Input/Output Channel)이라 한다.
> 입출력 채널이 있는 컴퓨터에서는 CPU가 입출력 채널에게 메모리에 저장된 특정 입출력 명령어를 수행하라고 지시한다.
